# feishu-agent

飞书群机器人：群里 @ 它 → 大模型 + 两个 MCP 工具服务 → 查完回群。SN 少的给可复制文本，明细多的附 CSV 文件。

**默认纯只读。** 写能力要显式开 `BOT_WRITE=1`，并且每一次真写都要人在卡片上点按钮确认。

## 三个值得看的设计

**一、多模型接入与熔断。** 主模型故障自动切备用，并且给挂掉的模型记 5 分钟冷却，冷却到期自动半开重试、成功即撤销。这条是踩出来的：不熔断的时候，主模型整个挂掉时每一轮都老实重试它、每次白等满 30 秒——一条两轮的查询有 **63 秒在等一个死模型**，而日志只显示「模型=备用」，没人看得出来。见 `lib/模型.mjs`。

**二、只准跑一个实例。** 起来先占 pid 文件，已有活着的就自己退出。这条也是踩出来的：机器上同时跑了两个 bot，同一句话被答了两遍，各烧一百多秒，而**两边日志各看各的都正常、退出码都是 0、飞书也不报错**——只有人在群里看见两条回复才知道。见 `lib/独占.mjs`。

**三、写操作拦在派发前。** 模型调用写工具时，工具一次都不会被真正执行：先返回「待确认」和参数原样，由人点卡片按钮，带着确认票重调才落库。拦的位置很关键——拦在派发后就等于「人还没点，已经写进去了」。见 `lib/护栏.mjs` 与 `lib/agent.mjs`。

其他：MCP 子进程死了立刻拒掉在等的请求并退出交给守护重启（不许"活着但每条都失败"）、长连接断线后把漏掉的消息补收回来、上下文快满时挪走最老的工具回包并留一句说明（不是悄悄删）、工具回包超长时截断**留印**让模型知道自己只看到一部分。

## 跑测试

```bash
./run-tests.sh        # 离线回归，约 5 秒
./run-tests.sh 全      # 加上打网络的那批，约 10 分钟
```

十项离线回归：护栏 185 条判据、agent 121 条、范围锁 50 条、补收 33 条、术语表 26 条、清单 22 条、问答留存 21 条、MCP 客户端 10 条、资源位置 9 条，另加静默棘轮；末尾还检查每个 `tests/*.test.mjs` 都在脚本里登记过（漏登记的测试等于永远不会跑），以及 eslint 扫过全部 42 个 `.mjs`。

**便宜那档跑完不会印得像全验过了**——它会明说「这轮没验答得对不对」。一个只验了一半的回归印出无差别的绿，比不跑更危险。
